# Upstream interfaces and design choices

**Muse Gadget SDK.** Its Linux client pairs out of band, establishes a Noise session, registers its commands, answers invocations with correlated results, and handles chat and audio on separate streams. This repo adapts the lifecycle with manual key exchange and a controller-initiated private HTTP link. It implements its own wire format. [Muse Linux implementation notes](https://github.com/facebookincubator/muse-gadget-sdk/blob/270e653066ed9d49fefca112054843f214775262/linux/AGENTS.md)

**Maestro person-device presence.** Maestro's registry accepts a device/person association and heartbeats. An optional raw base64 Ed25519 person-signing key has a distinct approval and revocation lifecycle. Hardware access here uses separately provisioned pins. The bridge does not impersonate a person, create presence records or read AID/AMP private keys. Dashboard person-key revocation and this bridge's local unpair are independent. [Person device model](https://github.com/23blocks-OS/ai-maestro/blob/30c893dc258b7a3bc7a4b95dcfccda6b2c4c3129/types/person-device.ts) · [Registry service](https://github.com/23blocks-OS/ai-maestro/blob/30c893dc258b7a3bc7a4b95dcfccda6b2c4c3129/services/person-devices-service.ts)

**AMP identity and delivery.** On the controller host, `announce` calls the installed `amp-send` executable using fixed arguments and the operator's configured AMP identity. Maestro's existing CLI handles signing and routing. This keeps AMP credentials separate from device pins. Incoming AMP messages do not trigger hardware operations. A future inbound adapter would need to validate sender identity and map that identity to explicit device grants. [AMP sender](https://github.com/23blocks-OS/ai-maestro-plugins/blob/main/plugins/ai-maestro/scripts/amp-send.sh) · [Maestro route endpoint](https://github.com/23blocks-OS/ai-maestro/blob/30c893dc258b7a3bc7a4b95dcfccda6b2c4c3129/app/api/v1/route/route.ts)

**Calls.** Maestro already has AMP-RTC call signaling. A later media profile can coordinate with that lifecycle. This implementation covers individual device operations. [Maestro RTC code](https://github.com/23blocks-OS/ai-maestro/blob/30c893dc258b7a3bc7a4b95dcfccda6b2c4c3129/lib/amp-rtc.ts)
